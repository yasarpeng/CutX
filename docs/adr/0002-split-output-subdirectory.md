# split 默认输出到子目录 cutx-<basename>/

split 默认将分片文件和清单文件输出到源文件所在目录下自动创建的子目录 `cutx-<basename-without-extension>/` 中，而非散落在当前目录。`-o` 参数完全替代此行为——用户指定 `-o /path/` 时，分片直接输出到该路径，不套子目录。

**为什么默认创建子目录**：100GB 文件切割后产生 50 个分片文件 + 1 个清单文件，直接散落在源文件目录会造成混乱。子目录让切割产物自包含，整个目录拷贝到 U 盘即可交付。

**为什么清单也进子目录**：merge 从 manifest 文件所在目录查找分片，清单和分片在同一子目录内，现有 merge 逻辑天然兼容，零改动。

**为什么 `-o` 不套子目录**：用户显式指定路径意味着"我知道放哪"，再套一层子目录反而违反预期。与当前 `-o` 语义一致，改动最小。

**考虑过的替代方案**：
- 分片进子目录、清单留外层：被否决，merge 需要改逻辑才能找到分片子目录，增加复杂度。
- `-o` 也套子目录：被否决，违反"用户指定就尊重"的直觉。
